Where everything lives

Four separate places hold four different things. Mixing them up caused most of the confusion.

1. Your PDFsSharePoint and your OneDrive: 2,785 unique files, 6.53 GB, 131,756 pages. A copy of the 25 pilot files sits in Azure storage (181.4 MB).
2. The reading stepOne-time. An AI service reads each page, finds tables and pictures, and records page numbers.
3. The searchable copyHeld by the Azure AI Search service. This is what has the 50 MB Free cap. Pilot: 63.3 MB.
4. The picture filesExtracted pictures saved as image files in Azure storage (container manuals-images). Pilot: 1,422 files, 125.6 MB. No size cap that matters.

Were the pictures ingested?

Yes. For each picture, the pipeline saved the image, asked an AI model (gpt-5-mini) to describe it in words, then stored that description and its numeric fingerprint (vector) in the search. In the pilot: 1,422 pictures, each described in about 400 characters, none left empty. Measured

Example from the index: "A handheld optical refractometer shown in isometric view. Main elements: a rear eyepiece on a short tube; a cylindrical focusing/adjustment knob…"

Proof it works: asked for the wheelchair ramp wiring diagram, the agent answered with the connector pins, wire sizes and relays, read from those descriptions, and pointed to pages 21, 30 and 31.

Limit. The agent never sees the pixels, only a 400-character description. A description can miss a small label or a part number printed on a drawing. How good the descriptions are on your real diagrams is not yet scored. Unknown This is a test we can run before Basic, on the pilot's 1,422 pictures.

Why the copy is bigger than the PDF

The copy is not a shrunken PDF. It is the text, plus a description of every picture, plus a numeric fingerprint (vector) for every piece so that search works by meaning. The fingerprints are the bulk.

The one-time page reading

What it is

The service is called Azure AI Document Intelligence, using its Layout model. Inside Azure AI Search it runs as the Document Layout skill. It is sold under Microsoft Foundry (formerly Azure AI services), and it is billed through an AI Services resource attached to the search. The ticket asks IT for one in Canada Central. Verified

What it does

It looks at each PDF page and returns structured content: headings, paragraphs, tables kept as tables, the page number, and the position of every picture.

Why it is required

Azure's plain text extraction is free but flattens tables, and in the pilot the page numbers came from the Layout step. Two things in your tests depend on the Layout reading: the page numbers in your citations, and torque tables. The pilot already used it, in a mode that flattens tables. That is why the same M6 question gave 15 Nm once and 12.7 Nm another time. The Basic rebuild uses a mode that keeps tables as tables.

When you pay

Once per page, when the manual is first processed. Not per question. If a manual is processed again, you pay again unless caching is switched on, which the rebuild plan includes. Verified

Why two passes

The table-friendly mode cannot extract pictures, so the rebuild design runs a second pass to get them. Azure's built-in picture extraction may do that job more cheaply. This is the largest saving on the table, and it is untested. Unknown The 1-file Basic trial settles it.

Terms

TermPlain meaning
Index, searchable copyWhat Azure AI Search stores so it can search fast. Not your PDFs.
Piece (chunk)A passage of text or one picture description, stored as one searchable item.
VectorA list of 1,536 numbers that captures a piece's meaning, so a search finds meaning and not only words.
PartitionA unit of storage and capacity inside one search service. Adding one adds capacity and cost, not a second subscription.
