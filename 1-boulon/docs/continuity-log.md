## Glossary

- **Knowledge tier 1 — authoritative (Greg, 2026-10-06)** = what BOULON started with: service manuals, maintenance manuals, parts catalogues, wiring diagrams. The agent's source of truth for specs, torque and safety.
- **Knowledge tier 2 — experience (Greg, 2026-10-06)** = what Henri and Pierre added: historical work orders (MIR), technician notes, previous symptoms. Advisory ("we recommend checking first", with the number of past cases); never overrides tier 1 on specs or safety.
- **Naming note:** dated entries below that say "Tier 1" mean the retired **exact-match lookup** (type a part number, get that record) and "Tier 2" means the **generative path** (AI reading the manuals). Those are older meanings; the two knowledge tiers above are the project's structure from 2026-10-06.
- **Azure AI Search ("the pilot")** = the new smart search engine indexing 25 of the 100+ manuals. It is now the *only* knowledge source connected to the live agent (SharePoint has been deliberately retired as a knowledge source for testing — see Decisions Log).
- **Generative orchestration** = the agent-wide setting where an AI planner decides, per message, which topic/tool/knowledge source should respond.
- **CMMS** = the software that logs a vehicle's maintenance/repair history. Not currently connected to this agent; references to it were removed from the agent's instructions (see Decisions Log).

## 1. Constitution — mandate and standing process rules

- Build in Copilot Studio / Microsoft-native tooling, but not a hard limit — Azure AI Search and other Microsoft-ecosystem tools are explicitly in scope.
- Answers must be evidence-grounded; never guess.
- Reporting line: overseer is Henri.
- BOULON's real scope is a holistic assistant for engineers/mechanics, not just part lookup.
- $5,000 CAD project budget, Greg's discretion.
- I (Claude) log project state and decisions directly in this doc — Greg should not have to do manual copy-paste logging.
- Plain, non-technical language by default; every technical term explained in plain words the first time it's used in a message, every time, not assumed remembered.
- Every proposed test includes the exact literal input string, where to run it, what confirms vs. what's a red flag, and what to report back — never a label alone (T1, T2…) without restating its full content in the same message.
- Every message ends with concrete next actions — never a dangling open question, never a status recap with nothing actionable.
- **Citation pass condition (2026-09-23):** a test passes only if the answer is right AND the citation names the actual manual. A citation showing the index name (`multimodal-rag-…`) is a FAIL.
- **Approval gate (2026-09-23, Greg):** nothing that costs money or requests a company resource is built until the approval route is confirmed. Claude prepares the request package first.
- **Locked company PC (2026-09-23, Greg):** software installs go through an IT ticket with a justification. Never suggest direct installs or workarounds.
- **No projections to Henri (2026-09-23, Greg):** reports and requests to Henri carry no future dates or deadlines unless he asks. Use undated steps.
- **ECC-first (2026-09-23, Greg):** use ECC agents, skills and tools at every occasion they fit. Each schedule slot names its ECC tool.
- Corpus size: 100+ manuals, some 600+ pages. Greg works continuously — don't suggest pauses.
- **Purchase tickets verified 100% (2026-09-24, Greg):** before calling any resource request ready, inventory the real region/type of every existing resource it touches, check every link on Microsoft Learn, include monthly AND one-time costs, use one connection style, and make every line understandable to Greg. Present it once, complete.
- **Authoritative evidence only (2026-09-24, Greg):** never claim something is unavailable or blocked from indirect evidence (e.g. a missing price-list line). Check the official table or run a test.
- **Two knowledge tiers (2026-10-06, Greg):** the chatbot is developed on two knowledge layers. Tier 1 (manuals) is authoritative; tier 2 (work orders, technician notes, symptoms) is advisory. Every answer must make clear which tier it came from, and for torque, specs and safety it points to tier 1. Gates are tracked per tier (see the Gate board).
- **Greg's PM mode (2026-10-06):** Claude acts as project manager on the phase/gate structure: every status states the gate, what blocks it, and the next moves that need no one else.
- **Measure before you quote (2026-10-06, Greg):** never state a size, page count or cost as fact unless it was counted; label every figure Measured, Verified (Microsoft table), Estimate or Unknown. Free checks (download, count, simulate) come BEFORE any paid step.
- **Use the saved files and the real clock (2026-10-06, Greg):** read saved project files and memory before asking Greg for something he already gave; plan with the real clock, never push same-day work to tomorrow.
- **Scope is the entire Manuels folder (2026-10-06, Greg):** there is no core library. Tier 2 (work orders) is parked. Claude is PM and reports to Greg only.
- **All scheduling lives in BOULON HQ (2026-10-06, Greg):** Today and Week tabs with click steps; ticket checks are never a scheduled task. No coverage statement for the agent.
- **Source of truth (2026-10-07, Greg): project brief 551, 4 May 2026** (`1-boulon/docs/project-brief-551.md`, scan in `1-boulon/docs/source-of-truth/`). Scope: workshops of Beloeil (QC), Sudbury (ON) and Kitimat (BC), 5 users each; French, English, Spanish; KPIs 95% agentic evaluation confidence and 7 requests per location per day; estimated project cost CAD 5,510.50.
